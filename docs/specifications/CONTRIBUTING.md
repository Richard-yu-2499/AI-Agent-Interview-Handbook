# CONTRIBUTING.md

# AI-Agent-Interview-Handbook Contribution Guide

## 1. Purpose

This document defines contribution standards for the
AI-Agent-Interview-Handbook.

The goal is to ensure all contributions maintain:

-   technical accuracy;
-   consistent structure;
-   professional writing quality;
-   long-term maintainability.

------------------------------------------------------------------------

# 2. Contribution Principles

Contributors should focus on:

## Technical Value

Content should improve readers' understanding of AI Agent systems.

## Engineering Relevance

Examples and explanations should connect with real-world development.

## Consistency

New content should follow existing handbook standards.

## Quality

Every contribution should pass review requirements.

------------------------------------------------------------------------

# 3. Contribution Types

Supported contributions include:

## New Chapters

Examples:

-   new Agent architectures;
-   emerging technologies;
-   advanced engineering topics.

------------------------------------------------------------------------

## Chapter Improvements

Examples:

-   clearer explanations;
-   additional examples;
-   improved diagrams.

------------------------------------------------------------------------

## Technical Corrections

Examples:

-   fixing inaccurate statements;
-   updating outdated information.

------------------------------------------------------------------------

## Interview Content

Examples:

-   new interview questions;
-   improved answers;
-   system design scenarios.

------------------------------------------------------------------------

# 4. Content Requirements

New content should include:

## Clear Structure

Follow:

    Introduction

    Core Concepts

    Architecture

    Implementation

    Trade-offs

    Interview Discussion

    Summary

------------------------------------------------------------------------

## Accurate Terminology

Use definitions from:

-   TERMINOLOGY.md
-   STYLE_GUIDE.md

Avoid inconsistent naming.

------------------------------------------------------------------------

## Engineering Perspective

Explain:

-   why a design exists;
-   how it works;
-   when to use it;
-   limitations.

------------------------------------------------------------------------

# 5. Writing Requirements

Contributors should:

-   use professional technical language;
-   explain concepts progressively;
-   avoid marketing-style descriptions;
-   avoid unsupported claims.

Content should focus on mechanisms rather than hype.

------------------------------------------------------------------------

# 6. Code Contribution Requirements

Code examples should:

-   be readable;
-   demonstrate correct patterns;
-   include necessary context;
-   avoid unnecessary complexity.

Consider:

-   error handling;
-   security;
-   maintainability.

------------------------------------------------------------------------

# 7. Diagram Contribution Requirements

Diagrams should:

-   follow DIAGRAM_GUIDE.md;
-   explain architecture clearly;
-   avoid decorative complexity.

Every diagram should provide educational value.

------------------------------------------------------------------------

# 8. Review Process

Contribution workflow:

    Create Change

          |

    Self Review

          |

    Submit Review

          |

    Technical Review

          |

    Quality Check

          |

    Merge

------------------------------------------------------------------------

# 9. Pull Request Checklist

Before submission:

## Content

-   Is the topic clearly explained?
-   Are concepts technically correct?

## Structure

-   Does it follow handbook style?
-   Are sections organized?

## Quality

-   Are examples useful?
-   Are trade-offs discussed?

## Consistency

-   Are terminology and formatting correct?

------------------------------------------------------------------------

# 10. Long-Term Maintenance

Contributors should consider:

-   future updates;
-   compatibility;
-   changing AI Agent ecosystem;
-   educational value.

The handbook should remain a reliable technical reference.

------------------------------------------------------------------------
