# QUALITY_CHECKLIST.md

> 本文档定义《AI-Agent-Interview-Handbook》项目在内容生产、代码示例、章节审核、发布维护过程中的质量检查标准。
>
> 目标是保证 Handbook
> 长期维护过程中保持一致的技术深度、表达质量和工程可信度。

------------------------------------------------------------------------

# 1. 文档目标

QUALITY_CHECKLIST.md 用于检查：

-   单个章节质量
-   技术内容准确性
-   代码示例质量
-   图示质量
-   术语一致性
-   引用规范
-   发布前完整性

核心目标：

> 每一个合并到主分支的文件，都应该达到可公开发布标准。

------------------------------------------------------------------------

# 2. 使用流程

质量检查贯穿：

1.  写作阶段
2.  Review 阶段
3.  Merge 阶段
4.  Release 阶段

推荐流程：

``` text
Draft

↓

Self Review

↓

Technical Review

↓

Language Review

↓

Merge

↓

Release
```

------------------------------------------------------------------------

# 3. Chapter 基础检查

## 3.1 结构检查

确认章节包含：

-   明确标题
-   学习目标
-   背景介绍
-   核心概念
-   技术分析
-   示例代码
-   总结
-   面试问题

------------------------------------------------------------------------

## 3.2 内容完整性

检查：

-   是否覆盖章节目标
-   是否存在关键知识缺失
-   是否存在跳跃推理
-   是否提供必要背景

------------------------------------------------------------------------

## 3.3 深度要求

避免：

-   只介绍定义
-   只介绍 API
-   只展示 Demo

应该包含：

-   原理
-   架构
-   Trade-off
-   工程实践
-   面试关注点

------------------------------------------------------------------------

# 4. 技术准确性检查

## 4.1 概念准确

检查：

-   定义是否正确
-   术语是否统一
-   是否存在过时描述

------------------------------------------------------------------------

## 4.2 架构准确

涉及：

-   Agent Architecture
-   Multi-Agent System
-   MCP
-   A2A
-   Memory
-   Tool Calling

需要确认：

-   组件职责正确
-   数据流正确
-   调用关系正确

------------------------------------------------------------------------

## 4.3 时间敏感内容

对于：

-   Model Capability
-   API Feature
-   Framework Version

需要标注：

-   更新时间
-   版本信息
-   适用范围

------------------------------------------------------------------------

# 5. 代码质量检查

## 5.1 基础检查

确认：

-   Code Fence 正确
-   Language 标识正确
-   缩进正确
-   示例逻辑正确

------------------------------------------------------------------------

## 5.2 可读性检查

代码应该：

-   命名清晰
-   注释合理
-   结构简单

避免：

-   超长代码
-   隐藏依赖
-   无解释复杂逻辑

------------------------------------------------------------------------

## 5.3 安全检查

禁止：

-   API Key
-   Token
-   Password
-   私有地址
-   用户数据

------------------------------------------------------------------------

## 5.4 Agent Code 检查

Agent 示例应该明确：

-   Agent Role
-   Input
-   Planning
-   Tool Usage
-   Execution
-   Output

------------------------------------------------------------------------

# 6. AI Agent 专项检查

## 6.1 Agent Workflow

检查是否说明：

-   Task Input
-   Planning
-   Action
-   Observation
-   Reflection
-   Final Response

------------------------------------------------------------------------

## 6.2 Tool Calling

确认：

-   Tool Schema 明确
-   参数说明完整
-   Error Handling 合理

------------------------------------------------------------------------

## 6.3 Memory

如果涉及 Memory：

需要说明：

-   Short-term Memory
-   Long-term Memory
-   Storage Strategy
-   Retrieval Strategy

------------------------------------------------------------------------

## 6.4 Multi-Agent

如果涉及 Multi-Agent：

需要说明：

-   Agent Role
-   Communication Pattern
-   Coordination Strategy
-   Failure Handling

------------------------------------------------------------------------

# 7. Diagram 检查

所有图示需要确认：

-   图例清晰
-   标签一致
-   箭头方向正确
-   与正文一致

避免：

-   装饰性图片
-   无解释图片
-   信息密度过低图片

------------------------------------------------------------------------

# 8. Terminology 检查

确认：

-   使用 TERMINOLOGY.md 统一术语
-   首次出现提供英文
-   缩写首次解释

例如：

正确：

``` text
Large Language Model (LLM)
```

错误：

``` text
大模型
```

无上下文说明。

------------------------------------------------------------------------

# 9. References 检查

引用内容需要：

-   来源可靠
-   信息可验证
-   格式统一

优先：

-   Official Documentation
-   Research Paper
-   Technical Report
-   Standards

避免：

-   无来源博客
-   二手转载
-   不可靠内容

------------------------------------------------------------------------

# 10. Interview 内容检查

面试相关章节需要包含：

## 基础问题

检查：

-   概念理解
-   定义解释

## 深入问题

检查：

-   原理分析
-   架构设计
-   Trade-off

## 工程问题

检查：

-   性能
-   稳定性
-   安全性
-   扩展性

## 开放问题

检查：

-   设计能力
-   系统思维
-   实际经验

------------------------------------------------------------------------

# 11. Writing Style 检查

确认符合：

-   STYLE_GUIDE.md
-   WRITING_GUIDE.md

检查：

-   语言专业
-   表达清晰
-   避免营销语言
-   避免绝对化结论

------------------------------------------------------------------------

# 12. Git Commit 检查

提交前确认：

``` text
git diff
```

检查：

-   修改范围明确
-   无临时文件
-   无调试代码
-   无生成文件污染

------------------------------------------------------------------------
